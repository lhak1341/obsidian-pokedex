# clearRange can't evict a regional-form variant via any per-generation Delete when its own generation differs from its base species' range

An architecture review (candidate 2, 6th round) flagged `getCacheStatus`/`clearRange`/`cacheRange` (`src/data/PokedexRepository.ts`) as reasoning about regional-form generation membership inconsistently: `clearRange`'s eviction swept a discovered variant regardless of whether the variant's own `generationId` matched the generation range being cleared — a real bug, confirmed live: deleting Gen 1's cache silently evicted Alolan Rattata's Gen 7-tagged data, since its base species (dex #19) sits in Gen 1's range even though `REGIONAL_FORMS.alola.generationId` is 7.

**Fix applied:** `clearRange` now gates the eviction on `REGIONAL_FORMS[form.suffix].generationId === generation.id`, closing the silent-wrong-generation-deletion bug (`getCacheStatus`'s comment and CLAUDE.md's cache gotcha updated to match).

**Gap this introduces, deliberately left as-is:** `clearRange(generation)` only ever iterates base dex ids inside `generation`'s own numeric range, then reads *that id's* cached species JSON to discover any regional-form variants. It never visits ids outside the range being cleared. For a variant whose own generation differs from its base species' dex range (Alolan Rattata: base range Gen 1, own generation 7), no per-generation Delete button's range ever reaches both "the base id whose species JSON reveals this variant" and "the variant's own generation" at the same time — Gen 1's Delete reaches the base id but is now correctly gated out; Gen 7's Delete has the matching generation id but its range (722-809) never reaches base id 19 to discover the variant at all. Confirmed live: after the fix, clicking Gen 7's Delete left `pokemon/rattata-alola.json` and `pokemon/10091.json` on disk, untouched.

Fixing this properly would require `clearRange`/`getCacheStatus` to discover a generation's regional variants independent of where their base species lives — e.g. listing every cached species file on disk and checking each one's derived regional forms, rather than iterating a numeric id range. `DiskCache` (`src/data/Cache.ts`) has no directory-listing method today (`exists`/`readJson`/`writeJson`/`remove` by exact path only) — adding one is a real capability expansion, not a small tweak, for what's a cosmetic gap (a variant's cache lingers longer than expected) rather than a correctness bug (data silently deleted from under an unrelated generation, which the fix above already closes).

**Decision:** leave this gap as-is. A regional-form variant whose own generation diverges from its base species' dex range can only be cleared via the plugin's global "Clear cache" button, never a per-generation Delete — this is the safer direction to err in (stale-but-present beats silently-wrong-deletion) and matches this repo's existing pattern of documented, deliberately scoped cache gaps (see ADR-0002's `getMegaForm` staleness gap, `getCacheStatus`'s own variant-undercounting). Don't re-flag this as a bug in a future review without first proposing a `DiskCache` directory-listing capability as its own decision — that's the actual lever, not further per-generation range gating.
