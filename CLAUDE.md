# obsidian-pokedex

House conventions for Obsidian plugin repos live in the `obsidian-plugin-dev` skill — bun, script contract, all Svelte 5 rune and scoping gotchas, `obsidian eval` mechanics, CSS specificity and containing-block traps, live-verification workflow. Repo-specific facts are below; deeper domain rules live in `src/data/CLAUDE.md` (fetch/cache/normalize), `src/view/CLAUDE.md` (UI/table/live-verify), and `docs/multi-gen-expansion-plan.md` (adding a generation).

Issue tracker: GitHub issues; wayfinding operations (sub-issues, blocking, claims) are in `docs/agents/issue-tracker.md`. A ticket's interface is shaped by the tickets that consume it: before settling a signature, read the parent spec's sections for those later tickets (#19's cache port first returned data URIs; #21's blob-URL LRU needs bytes).

Deploys to the vault folder `pokedex` (intentionally ≠ manifest id `lhak-pokedex`), and to `pokedex-test-vault/` (named so the Obsidian CLI's by-name `vault=` cannot hit a sibling repo's `test-vault`; `vault=` counts only before the subcommand — `obsidian eval vault=…` silently runs in the focused vault, the real one). `bun run deploy` writes both, so a test-vault-only live check copies the build instead (`docs/mobile-verification.md` step 1).

Inline comments here are unusually thorough and load-bearing. Most "shallow module" or "duplicate logic" findings from automated architecture review turn out to be deliberate, already-documented separations once the comments are read (6 of 8 candidates misdiagnosed in one round, 3 of 5 in another). Reread the full file and check for an existing ADR in `docs/adr/` before writing a candidate into a report — not only before implementing one. An ADR's description of the code is a dated snapshot, so check its factual premises against the code before letting it rule a candidate out (ADR-0010's "prefetch calls `getEntryExtras`" had been false since #21, and the gap behind it was a review's top finding).

## Repo-specific toolchain

`bun run check` (typecheck, lint:ratchet, lint:styles, test) is the gate. `.github/workflows/ci.yml` runs it plus `build` and `verify:release` on every push and PR, and `release.yml` reruns them before publishing — a tag can be pushed from a commit CI never saw. Nothing below is a "remember to" any more; it explains why the gate is shaped the way it is.

- `bun run build` transpiles with esbuild and never typechecks, so a green build proves nothing about types (verified: a deliberate type error builds clean).
- `bun run typecheck` is `svelte-check`, not `tsc`: it checks `.ts`, `scripts/*.ts` and every `.svelte` template and prop, and reports Svelte compile errors. Plain `tsc` types a `.svelte` import as Svelte's ambient `Record<string, any>` shim, so it rejects `PokedexView`'s uncast `mount` while missing every template error; don't put it back in the chain. It does not flag an unused scoped CSS selector (probed: a dead rule passed `--fail-on-warnings`), so CSS moved between components is checked by cross-referencing each file's template classes against its own `<style>`.
- TypeScript 6 does not auto-include `@types/*`, so `node:fs` in a test fails typecheck even with `@types/node` installed. Read source text with Vite's `?raw` (declared in `src/raw-imports.d.ts`). A test that must run Node itself (esbuild, stylelint, a vendored file) adds `/// <reference types="node" />` at its top (`src/styles.test.ts`); `.css?raw` comes back empty under vitest, so read CSS from disk there.
- `vitest run` with its output redirected drops a passing test's `console.*` lines (probed: 0 of 2 printed); a throwaway probe test runs with `--silent=false --reporter=verbose` (both printed), or reports by throwing its readings.
- `tsconfig.json` targets ES2020, so `Array.prototype.at()` (ES2022) fails typecheck with a misleading "change your target library?" error. Use `arr[arr.length - 1]`; do not bump the target (Obsidian runtime compat risk).
- Typecheck forces a per-key piece only through a `Record<Key, …>`, a `never` fallback (`unhandledCustomCell`), or a switch whose return type excludes `undefined`; `noImplicitReturns` is off, so a switch returning `T | undefined` compiles with a case missing (`filterGroupCount` did, until ADR-0027). To learn what a new key really forces, add a throwaway one and read svelte-check's errors; a per-key test table typed `Record<Key, …>` (`GROUP_SAMPLES`) forces a new key's test too.
- No rule can be disabled by an inline comment (`eslint-comments/no-restricted-disable` set to `*` in `eslint.config.mjs`): fix the underlying issue. This also rules out vitest's asymmetric matchers (`expect.any`, `arrayContaining`, `objectContaining` all return `any`, trips `no-unsafe-assignment`): assert a plain boolean (`list.includes(x))` or `Object.keys(...)` plus `typeof x` instead.- Every obsidianmd rule this repo trips is warn-severity, so `bun run lint` exits 0 however many it reports; `bun run lint:ratchet` is the gate. It pins the warning count both ways, so paying warnings down means lowering `BASELINE` in `scripts/lint-ratchet.mjs` in the same commit.
- A new UI string with a brand acronym ("HOME") passed to `setText` or a `Notice` adds a sentence-case warning, which alone fails the ratchet; reword rather than raise `BASELINE`. Text in a `.svelte` template is not checked (probed 2026-11-28).
- A release tag is the bare version string (`0.1.1`), not `v`-prefixed: `release.yml`'s `verify:release` string-matches it against `manifest.json`'s version, so a wrong format fails only after the tag is pushed.

## Styles (@lhak/style)

PKDX reads the `@lhak/style` contract (vendored at `vendor/lhak-style`; re-vendor with `node scripts/vendor.mjs ../obsidian-pokedex` from lhak-style-guide, then `bun install`). `styles.css` is generated from `styles.src.css` by esbuild (`scripts/styles.mjs`) and gitignored; edit the source. Component CSS stays in each `.svelte` `<style>` and reads `--lk-` roles, which resolve only under `.lk-root` (`PokedexView`'s `contentEl`).

- A colour literal goes only in `src/styles/pokemon-colours.css` (the Pokémon type and stat colours, domain data), which `TYPE_COLORS`/`STAT_COLORS` read through `var()` names; any other colour takes a `--lk-` role. PKDX's own variables take `--pkdx-`.
- Under Obsidian, `--lk-surface-raised` is `--lk-surface` (both `--background-primary`) and `--lk-surface-sunken` differs by ~2%, so a panel filled with either vanishes against the view: separate it with `--lk-border-strong` or a `color-mix` tint of `--lk-text`.
- Svelte appends each component's `<style>` to the end of `<head>` at first mount, after the plugin's `styles.css`, and its scoped selectors carry an extra class. So a scoped rule beats a kit pattern rule of the same shape. Obsidian's `button` rules beat the chip pattern's rest state; `button.filter-chip` in `styles.src.css` restates them.

`temp/` is gitignored scratch, purged automatically — prefer it over the OS tmp dir, and never cite a `temp/` path from an ADR or doc (inline the probe method instead).
